# MWWorks — каталог и административная панель

## Назначение

MWWorks — сайт мастерской изделий из металла и дерева. Публичная часть показывает ассортимент и форму обращения, а административная панель позволяет поддерживать каталог в актуальном состоянии.

Актуальные точки входа:

- `/` — публичный сайт;
- `/admin` — административная панель;
- `/api` — HTTP API приложения.

## Функциональные границы

### Публичная часть

Публичный сайт содержит промо-блок, каталог, преимущества и форму заявки. Статус успешной отправки формы сейчас является клиентским: заявка не сохраняется и не передаётся в backend. Подключение CRM, почты или отдельного API заявок — следующая самостоятельная задача.

### Административная панель

После входа администратор может:

- видеть количество категорий и товаров;
- создавать, редактировать и удалять категории каталога;
- выбирать категорию и управлять товарами внутри неё;
- загружать или заменять изображение категории и товара;
- отменять редактирование и выйти из панели;
- получить понятное сообщение об успешной операции или ошибке API.

При удалении категории удаляются её товары и связанные с ними изображения. Удаление товара также удаляет его изображение. Перед удалением интерфейс требует подтверждение.

## Авторизация и доступ

В приложении предусмотрена одна серверная роль: `Admin`.

1. Клиент отправляет имя пользователя и пароль в `POST /api/auth/login`.
2. При успешной проверке backend возвращает JWT.
3. Панель сохраняет токен в `localStorage` под ключом `adminToken` и передаёт его в защищённые запросы как `Authorization: Bearer <token>`.
4. Все операции изменения каталога доступны только пользователю с ролью `Admin`.

Срок действия JWT и учётные данные администратора задаются серверной конфигурацией. В production секреты, пароль администратора и строка подключения не должны попадать в репозиторий или клиентскую сборку.

## Модель данных

### Category

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | UUID | Идентификатор категории |
| `name` | string, до 200 | Название |
| `description` | string, до 4000 | Описание |
| `imageId` | UUID | Связанное изображение |
| `createdAt` | datetime with offset | Время создания |

Одна категория содержит ноль или более товаров.

### Product

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | UUID | Идентификатор товара |
| `categoryId` | UUID | Родительская категория |
| `name` | string, до 200 | Название |
| `description` | string, до 4000 | Описание |
| `imageId` | UUID | Связанное изображение |
| `createdAt` | datetime with offset | Время создания |

### ImageEntity

Изображения хранятся в базе данных вместе с исходным именем файла, MIME-типом, бинарными данными, alt-текстом и датой создания. Alt-текст сейчас автоматически формируется из названия категории или товара.

Backend принимает только файлы с MIME-типом `image/*`, непустые и размером не более 10 МБ.

### DesignProject

Проект хранит эскиз мебели или небольшого каркаса. В нём есть `id`, название (до 200 символов), время создания и последнего изменения, а также `sceneJson` — сериализованная сцена.

Сцена содержит массив параллелепипедов. Для каждого объекта сохраняются название, цвет, размеры `length`, `width`, `height` в миллиметрах, координаты в миллиметрах и поворот вокруг осей X/Y/Z в градусах. JSON перед сохранением проверяется backend на синтаксическую корректность.

## API

Все запросы и ответы используют JSON, кроме создания и изменения элементов каталога: для них используется `multipart/form-data`.

### Авторизация

| Метод | URL | Доступ | Тело / результат |
| --- | --- | --- | --- |
| `POST` | `/api/auth/login` | публичный | JSON `{ "username", "password" }`; ответ `{ "token" }` |

При неверных учётных данных возвращается `401 Unauthorized`.

### Каталог

| Метод | URL | Доступ | Назначение |
| --- | --- | --- | --- |
| `GET` | `/api/categories` | публичный | Все категории вместе с товарами; категории и товары упорядочены по названию |
| `GET` | `/api/categories/{id}` | публичный | Одна категория с товарами |
| `POST` | `/api/categories` | `Admin` | Создать категорию |
| `PUT` | `/api/categories/{id}` | `Admin` | Изменить категорию |
| `DELETE` | `/api/categories/{id}` | `Admin` | Удалить категорию, её товары и изображения |
| `POST` | `/api/categories/{categoryId}/products` | `Admin` | Создать товар |
| `PUT` | `/api/categories/products/{id}` | `Admin` | Изменить товар |
| `DELETE` | `/api/categories/products/{id}` | `Admin` | Удалить товар и его изображение |
| `GET` | `/api/images/{id}` | публичный | Получить файл изображения |

### Проектирование

Все методы этого раздела требуют JWT с ролью `Admin`.

| Метод | URL | Назначение |
| --- | --- | --- |
| `GET` | `/api/design-projects` | Список проектов без содержимого сцены |
| `GET` | `/api/design-projects/{id}` | Проект и его `sceneJson` |
| `POST` | `/api/design-projects` | Создать проект: JSON `{ "name" }` |
| `PUT` | `/api/design-projects/{id}` | Сохранить название и сцену: JSON `{ "name", "sceneJson" }` |

Тело создания категории или товара:

```text
multipart/form-data
name: string, required, max 200
description: string, required, max 4000
image: file, required
```

Тело обновления имеет те же поля, но `image` необязательно: если файл не передан, сохраняется текущее изображение.

Ответ категории:

```json
{
  "id": "uuid",
  "name": "Костровые чаши",
  "description": "Описание",
  "imageUrl": "/api/images/uuid",
  "createdAt": "2026-01-01T00:00:00+00:00",
  "products": []
}
```

Ответ товара содержит `id`, `categoryId`, `name`, `description`, `imageUrl` и `createdAt`.

## Клиентское приложение

Frontend построен на React 18 и Vite. Публичная часть и `/admin` обслуживаются одной сборкой; переключение интерфейса происходит по `window.location.pathname`.

Административный экран должен оставаться удобным на узких экранах: карточки категорий, форма товара и список товаров переходят в одну колонку. Кнопки редактирования и удаления имеют текстовые подсказки, а изображения отображаются как миниатюры без влияния на размеры строк.

В «Проектировании» администратор сначала выбирает или создаёт проект, затем открывает 3D-редактор. Редактор использует перспективную камеру, зум колёсиком и панорамирование правой кнопкой мыши. Toolbar создаёт параллелепипед с размерами по умолчанию; правый инспектор редактирует его название, цвет, размеры в миллиметрах, координаты и поворот. Выбранный объект также можно перемещать и вращать 3D-манипулятором, а размеры менять ручками граней и углов.

Кнопка «Сохранить» отправляет проект немедленно. Если проект изменён, автосохранение выполняется раз в минуту; ошибка не очищает несохранённые изменения.

## Архитектура backend

Backend работает на .NET 8 и разделён на слои:

```text
Api             HTTP-контроллеры, контракты, авторизация
Application     сущности и интерфейсы сервисов/репозиториев
Infrastructure  Entity Framework Core, PostgreSQL, реализация сервисов
WebApi          точка запуска и композиция приложения
```

Каталог обслуживает `CatalogService`. Он создаёт и заменяет изображения вместе с сущностями каталога, а удаление выполняет в рамках одной операции сохранения изменений.

## Развёртывание

Для контейнерного запуска используется `deploy/docker-compose.yml`:

- backend публикуется на `5000`;
- frontend публикуется на `5173`;
- PostgreSQL ожидается во внешней Docker-сети `danetwork`;
- строка подключения и ключи должны передаваться через переменные окружения или безопасное хранилище секретов.

Локальная разработка frontend: `npm run dev` из `react-app`. Production-проверка сборки: `npm run build`.

## Не входит в текущую реализацию

- несколько ролей, управление пользователями и журнал действий;
- отдельное API для заявок из публичной формы;
- сортировка категорий и товаров вручную;
- оптимизация/ресайз изображений и внешнее объектное хранилище;
- автоматический выход в клиенте при истёкшем токене.
- удаление проектов, совместное редактирование, история версий, экспорт CAD/3D-форматов и библиотека готовых элементов.

Эти возможности следует проектировать отдельными задачами с обновлением API, модели данных и интерфейса.
